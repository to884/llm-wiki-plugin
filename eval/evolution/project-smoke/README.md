# プロジェクトのワークフローのスモーク試験

この小さなコーパスは、`README.md`、`CONTRIBUTING.md`、`skills/llm-wiki/assets/SCHEMA.md.template` に書かれている、このリポジトリの既存の取り決めをまとめたものである。対象は、正本となる Markdown、ローカルの埋め込み、ソースを変更してよいかどうか、リリースのバージョンを記すフィールドである。架空の Lark を使ったパイロットとは別物で、本番向けのベンチマークでもない。

2026-09-12 に、空のスキルから始める実行で、学習、統合、新しいスキルの提案、検証、固定した状態での最終テスト、Claude Code への転用評価までを完了した。使ったのは Codex CLI 0.153.4 と `gpt-5.6-luna` である。Claude Code 2.1.263 は、`sonnet` エイリアスの使用量として、`claude-sonnet-5` と補助の `claude-haiku-4-5-20251001` を報告した。どちらの CLI も既存のサブスクリプションを使った。Codex は実測の USD を報告しないので、費用の合計は null のままである。

候補は検証でベースラインと同点（どちらも1件合格）だったため却下され、インストール済みのスキルは変わっていない。最終タスクの4回の実行は、どれも正しい JSON の成果物を作った。最初の意味評価のグレーダーは成果物の引用ラベルをでっち上げ、証拠のバリデーターがそれを正しく拒否した。現在のジャッジのスキーマでは、証拠のソースを実在するソースのキーに限っている。保存しておいた4件の回答を再評価すると、4/4 で合格した。この再評価の結果を使って、候補の選定をやり直してはいない。元の最終スコアと実行環境のハッシュは、修正後のスコアで置き換えず、`live-results.json` にそのまま残している。

それ以前の実地のチェックでは、出力パスがあいまいな問題と、メンテナーがタスク ID ではなく説明文を証拠として返す問題も見つかった。共通のランナーは現在、wiki からの相対パスで出力先を指定し、ジャッジには成果物を測定した観測結果を渡し、出力スキーマでメンテナーの証拠 ID を制限している。raw の観測結果は、統合の前に記録する。オフラインの回帰テストで、これらの取り決め、実行時の予算、テストの再利用、ワークスペースの境界、ソースからの引用、複数ファイルの復旧を確かめている。

この試験で確かめたのは実行時の動作であり、モデルの品質が上がったことではない。分割ごとのタスクは1件、繰り返しは1回で、提案が却下されたあとは、最終テストのベースラインと選ばれたスキルが同一だった。効果を報告するのは、新しい最終タスクを使った、より大規模で代表的な調査を行ってからにする。実地のサイクルでは、固定した実行環境のスナップショットを使った。そのあとに入った履歴、対象の検証、記録処理の変更は、現在のオフラインテストで確かめている。

このワークフローを再現するには、`../pilot/config.example.json` をコピーし、認証済みのランナーと正確なモデル ID を選び、反復を1回、繰り返しを1回に設定し、ランナーの呼び出しを最大 24 回まで許可する。新しく作った使い捨ての学習用 wiki と空の作業用スキルディレクトリを使い、`suite.json` に対して `wiki_evolve_loop.py` を実行する。2つ目のエージェントでのチェックを再現するには、Claude への転用評価の項目を追加する。公開済みのこの最終タスクを、汎化の証拠として再利用してはならない。
